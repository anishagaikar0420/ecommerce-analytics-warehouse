# Power BI model and build guide

**Status: model assets only. The `.pbix` report is not included.** Power BI Desktop is Windows-only, so the report must be built
on a Windows machine (or a Windows VM / virtual lab). Everything the report needs is here and generated by `make run`:

| File | Purpose |
|---|---|
| `data/*.csv` | Star schema export (git-ignored, created by `make run`): `fact_sales` + 4 dimensions + `cohort_retention` |
| `load.pq` | Power Query (M) scripts that load and type each CSV |
| `measures.dax` | 26 DAX measures (sales, customers, fulfilment, time intelligence) |
| `theme.json` | Report theme (same palette as the HTML dashboard) |
| `expected_values.csv` | The correct value of each measure, computed in SQL, to **verify your DAX** |

> The DAX and M were written without access to Power BI Desktop and have not been run in it. Use `expected_values.csv` to check
> every measure after you create it, and fix anything that differs.

## 1. Load the data
1. Run `make run`, then copy `powerbi/data` to the Windows machine.
2. Power BI Desktop → **Transform data → Manage parameters → New**: text parameter `DataFolder` = path to that folder.
3. For each block in `load.pq`: **New source → Blank query → Advanced editor**, paste the block, rename the query to the table name
   in its comment (`fact_sales`, `dim_customer`, `dim_product`, `dim_date`, `dim_payment_method`, `cohort_retention`). **Close & apply.**

## 2. Model
In **Model view**, create these relationships (many-to-one, single direction, dimension → fact):

| From (many) | To (one) |
|---|---|
| `fact_sales[customer_key]` | `dim_customer[customer_key]` |
| `fact_sales[product_key]` | `dim_product[product_key]` |
| `fact_sales[date_key]` | `dim_date[date_key]` |
| `fact_sales[payment_method_key]` | `dim_payment_method[payment_method_key]` |

Then: select `dim_date` → **Table tools → Mark as date table** → date column `full_date`. Leave `cohort_retention` unrelated.
Hide key columns in report view. Sort `dim_date[year_month]` is already sortable as text (YYYY-MM).

## 3. Measures
Home → **Enter data** → create an empty table `_Measures`. For each measure in `measures.dax`: **New measure**, paste the definition.
Format: `%` measures as percentage; `Revenue*`, `Gross *`, `Discount Amount`, `AOV`, `Revenue per Customer` as currency.

**Verify:** make a table visual with no filters containing all measures and compare with `expected_values.csv`
(e.g. Revenue 16,340,171.84; Orders 52,856; Repeat Rate % 52.25%). For the year/month rows, add `dim_date[year]` / `year_month`
slicers: `Revenue PY` with year = 2024 must equal the 2023 revenue; `Revenue PM` for 2024-12 must equal November.

## 4. Report (View → Themes → Browse for themes → `theme.json`)

**Page 1 – Overview**
- Cards: `Revenue`, `Gross Margin %`, `Orders`, `AOV`, `Customers`, `Repeat Rate %`
- Line chart: `dim_date[year_month]` × `Revenue`, `Gross Profit`
- Clustered column: `year_month` × `Revenue YoY %` (2024 months)
- Slicers: `dim_date[year]`, `dim_customer[country]`

**Page 2 – Products & customers**
- Bar: `dim_product[category]` × `Revenue`, with `Revenue % of Total` in tooltips
- Bar (Top N filter = 10 by `Revenue`): `dim_product[product_name]`
- Matrix: rows `cohort_retention[cohort_month]`, columns `months_since_first`, values `retention_pct` (Don't summarize/Average),
  conditional formatting → background colour scale (leave month 0 at 100)
- Table: top customers by `Revenue per Customer`

**Page 3 – Operations**
- Line: `year_month` × `Cancel Rate %`, `Return Rate %`
- Donut/bar: `dim_payment_method[payment_method]` × `Revenue`
- Bar: `dim_customer[country]` × `Revenue`
- Cards: `Cancelled Orders`, `Returned Orders`, `Discount %`

Add a text box on each page: "Synthetic data". Save as `ecommerce_dashboard.pbix`, then publish to **Power BI Service** (free work/school
account may be required) and add the link to the top-level README. Only claim what you built: DAX measures count = number you
actually created in the file.
